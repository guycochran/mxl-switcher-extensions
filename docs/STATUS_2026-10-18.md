# Integrated eight-source status — 2026-10-18

This note records the current public-safe engineering boundary after the first
operated eight-source layout, confidence, audio, and 4K destination session.
It supersedes any interpretation of the earlier transport demonstration as a
combined production acceptance result.

## What worked

- Eight paired ZoomISO MXL video/audio sources were discovered and operated.
- Program, Preview, the ATEM-style control surface, and one browser multiview
  were available together.
- Warm layout banks exercised the defined 2-up through 8-up presets, including
  the balanced 5-up and 7-up designs.
- The 4K RTMPS path reached the destination without reconnecting.
- The diagnostic clock demonstrated that the encoder could produce smooth
  motion when the source and host were healthy.

## What did not pass

The combined single-host profile is **not broadcast-ready**. During the
eight-source 4K transmission on the 32-vCPU reference host:

- whole-host idle fell to roughly 9 percent and load exceeded available CPU;
- encoded video fell to roughly 21--23 fps;
- source lateness reached approximately 2.3--3.7 seconds; and
- the audience heard choppy Program audio even though the controller reported
  48 kHz AAC advancing at roughly 46--49 buffers/s with zero reconnects.

The audio observation exposes a detector gap: downstream AAC cadence can look
healthy while bounded, leaky per-source queues discard or replace upstream
audio under scheduler pressure. Machine readiness never overrides an audience
failure.

The operated switching sequence also reproduced a small number of terminal
torn confidence reads. Core routing hard counters remained stable during the
holds, but the confidence reader still needs the pending short-copy correction
before another promotion run.

## Architecture decision

The production node should protect deterministic switching and confidence
operations from destination encoding load. The preferred product boundary is:

```text
Contribution -> MXL production node -> final Program handoff
                                      -> MXL Streaming Egress Module -> RTMPS
```

The **MXL Streaming Egress Module** is a separately restartable and separately
sized bolt-on. A destination failure must not interrupt Core, Program Audio,
or operator control. The economical quick-start may retain a co-located 1080p
egress service after it passes its own capacity gate; 4K30 should be qualified
as an independent egress profile, with hardware encoding optional rather than
required by Core.

MXL shared memory is host-local. A separate VM cannot directly subscribe to a
Program flow from another VM. A two-node deployment therefore requires one
explicit, measured network handoff carrying the final Program video and audio.
The repository does not yet claim that bridge is implemented or accepted.
Candidate handoffs include a single SRT/RIST contribution, full-bandwidth NDI,
or a future standards-based IP media path. The choice must be made by measuring
end-to-end cadence, latency, A/V synchronization, CPU, and failure recovery;
it must not recreate eight contribution encodes merely to move the encoder.

## Next implementation gate

1. Replace the inline eight-source destination audio mix with the qualified
   index-domain Program Audio mixer and its single stable output flow.
2. Expose truthful Program Audio fault counters and meters in the operator
   surface; fail on held, skipped, missing, torn, invalid, offline, write, or
   progress faults.
3. Apply and qualify the confidence-reader short-copy correction.
4. Define and benchmark the single final-Program network handoff for the
   separately sized Streaming Egress Module.
5. Repeat with a 60-second smoke, then one 30-minute combined gate while the
   ATEM multiview remains open. Require full video cadence, at least 20 percent
   host headroom, zero hard faults/reconnects, audible clean Program audio,
   acceptable A/V sync, and two audience frames with advancing timecode.

Until that sequence passes, the supported claim remains a reproducible
technical preview and a successful set of component demonstrations—not an
unattended production appliance.
